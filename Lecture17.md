## 1. What is MongoDB?

MongoDB is a **NoSQL database** that stores data in flexible, JSON-like documents (called BSON — Binary JSON). Unlike relational databases (MySQL, PostgreSQL), MongoDB does **not** use tables and rows — it uses **collections** and **documents**.

| Relational DB | MongoDB |
|---|---|
| Database | Database |
| Table | Collection |
| Row | Document |
| Column | Field |
| Primary Key | `_id` field |

MongoDB is schema-less, meaning each document in a collection can have different fields.

---

## 2. Collections & Documents

A **document** is a single record, stored as a JSON-like object:

```json
{
  "_id": ObjectId("..."),
  "name": "Student1",
  "age": 21,
  "city": "Delhi",
  "email": "s1@gmail.com",
  "course": "BCA"
}
```

A **collection** is a group of related documents — similar to a table. Collections are created automatically when you first insert data.

---

## 3. Inserting Data

### Insert a Single Document
```js
db.students.insertOne({ name: "Alice", age: 20 });
```

### Insert Multiple Documents
```js
db.students.insertMany([
  { name: "Alice", age: 20 },
  { name: "Bob",   age: 22 }
]);
```

`insertMany()` returns an object with `acknowledged: true` and a map of `insertedIds`, each being a unique `ObjectId` generated by MongoDB automatically.

### Count Documents
```js
db.students.countDocuments();   // returns total count
```

---

## 4. Querying Data — `find()`

### Fetch All Documents
```js
db.students.find();
```

### Fetch with a Filter
```js
db.students.find({ city: "Delhi" });       // exact match
db.students.find({ age: 25 });             // numeric match
db.students.find({ course: "BTech" });     // string match
```

### Fetch Only One Document
```js
db.students.findOne();                     // returns first document
db.articles.findOne();                     // useful for inspecting structure
```

### Comparison Operators
```js
db.students.find({ age: { $gt: 22 } });   // greater than
db.students.find({ age: { $gte: 22 } });  // greater than or equal
db.students.find({ age: { $lt: 22 } });   // less than
db.students.find({ age: { $in: [20, 21] } }); // matches any value in array
```

## 5. Indexes in MongoDB

### What is an Index?

An **index** is a special data structure that stores a small portion of the collection's data in a sorted form. It makes queries **faster** by allowing MongoDB to jump directly to matching documents rather than scanning the entire collection.

> **Without an index:** MongoDB reads every document (COLLSCAN — Collection Scan).  
> **With an index:** MongoDB jumps directly to matching entries (IXSCAN — Index Scan).

### Creating an Index

```js
// Ascending index on "age" field
db.students.createIndex({ age: 1 });

// Descending index
db.students.createIndex({ age: -1 });
```

`1` = ascending order, `-1` = descending order.

MongoDB names the index automatically: `age_1` for `{ age: 1 }`.

### Viewing All Indexes
```js
db.students.getIndexes();
```

### Dropping an Index
```js
db.students.dropIndex("age_1");
```

---

## 6. Types of Indexes

### 6.1 Single Field Index
Index on one field. Most common type.
```js
db.students.createIndex({ age: 1 });
```

### 6.2 Compound Index
Index on multiple fields together. The **order of fields matters**.
```js
db.students.createIndex({ city: 1, age: -1 });
```
This supports queries on `city` alone, or on `city + age` together, but NOT on `age` alone.

### 6.3 Text Index
Used for **full-text search** within string fields. MongoDB only allows **one text index per collection**.
```js
db.articles.createIndex({ content: "text" });
```

### 6.4 Unique Index
Ensures no two documents have the same value for the indexed field.
```js
db.students.createIndex({ email: 1 }, { unique: true });
```

### 6.5 Sparse Index
Only indexes documents that **contain the indexed field** (skips documents where the field is missing).
```js
db.students.createIndex({ phone: 1 }, { sparse: true });
```

## 7. The `explain()` Method

`explain()` is used to **analyze how MongoDB executes a query**. It shows which plan was chosen, whether an index was used, and performance statistics.

### Syntax
```js
db.collection.find({ field: value }).explain("mode");
```

### Explain Modes

| Mode | What it shows |
|---|---|
| `"queryPlanner"` | Which plan MongoDB chose (winning plan), without executing |
| `"executionStats"` | Executes the query and shows real stats (documents examined, time taken) |
| `"allPlansExecution"` | Runs all candidate plans and shows stats for each |

---

### 7.1 `queryPlanner`

Does **not** actually run the query. Just tells you the winning plan (what MongoDB *would* do).

```js
db.students.find({ age: 25 }).explain("queryPlanner");
```

**Key fields to look at:**
- `winningPlan.stage` → `COLLSCAN` (no index) or `FETCH` + `IXSCAN` (index used)
- `rejectedPlans` → Alternative plans that were considered but not chosen

---

### 7.2 `executionStats`

**Actually executes** the query and returns real performance numbers.

```js
db.students.find({ age: 25 }).explain("executionStats");
```

**Key fields to look at:**

| Field | Meaning |
|---|---|
| `nReturned` | Number of documents returned to the user |
| `totalDocsExamined` | Total documents MongoDB had to look at |
| `totalKeysExamined` | Total index keys scanned |
| `executionTimeMillis` | Total time taken in milliseconds |

> **Ideal situation:** `nReturned ≈ totalKeysExamined` and `totalDocsExamined` is low. This means the index was used efficiently.

**Example interpretation — WITHOUT index (COLLSCAN):**
```
nReturned:         33
totalDocsExamined: 100   ← had to scan ALL 100 documents
totalKeysExamined:  0    ← no index used
```

**Example interpretation — WITH index (IXSCAN):**
```
nReturned:         16
totalDocsExamined: 16    ← only examined matching documents
totalKeysExamined: 16    ← index was used
```

---

### 7.3 `allPlansExecution`

Runs all candidate plans (not just the winner) and shows their stats. Useful for understanding why MongoDB chose one plan over another.

```js
db.students.find({ age: 25 }).explain("allPlansExecution");
```

## 8. COLLSCAN vs IXSCAN

These are the two most important **query execution stages**:

| | COLLSCAN | IXSCAN |
|---|---|---|
| Full form | Collection Scan | Index Scan |
| How it works | Reads every document one by one | Uses index to jump to matching entries |
| When it happens | No index exists for queried field | An index exists for the queried field |
| Performance | Slow on large collections | Fast |
| `totalDocsExamined` | Equal to total documents | Only matching documents |

### How a Query Execution Works WITH an Index

When an index exists, MongoDB executes in two stages:
1. **IXSCAN** — Scans the index to find matching keys (very fast, index is sorted)
2. **FETCH** — Uses those keys to fetch the full documents from disk

This is why you see `stage: 'FETCH'` with an `inputStage: { stage: 'IXSCAN' }` in the explain output.

```
winningPlan: {
  stage: 'FETCH',          ← Step 2: get full documents
  inputStage: {
    stage: 'IXSCAN',       ← Step 1: scan the index
    indexName: 'age_1'
  }
}
```

## 9. Text Search & Text Indexes

MongoDB's **text index** enables full-text search on string fields. It tokenizes words, removes stop words (like "is", "the", "and"), and stores the remaining tokens.

### Creating a Text Index
```js
db.articles.createIndex({ content: "text" });
// Index name: "content_text"
```

### Searching with `$text`
```js
db.articles.find({ $text: { $search: "Java" } });
```

This finds all documents where the `content` field contains the word "Java".

### Important Rules About Text Indexes

> **MongoDB only allows ONE text index per collection.**

If a text index already exists on `content`, you cannot create another on `title`:

```js
db.articles.createIndex({ title: "text" });
// ❌ MongoServerError[IndexOptionsConflict]
```

**Solution:** Create a **compound text index** covering both fields at once:
```js
db.articles.createIndex({ content: "text", title: "text" });
```

You can also assign different weights to fields:
```js
db.articles.createIndex(
  { title: "text", content: "text" },
  { weights: { title: 10, content: 1 } }
);
```
With weights, matches in `title` rank higher than matches in `content`.

## 10. Text Search Operators

### Search for a Single Word
```js
db.articles.find({ $text: { $search: "Java" } });
// Returns all articles mentioning "Java"
```

### Search for Multiple Words (OR logic)
```js
db.articles.find({ $text: { $search: "Java programming" } });
// Returns articles that mention "Java" OR "programming" (or both)
```

Text search with multiple words is **OR by default**, not AND. Both terms are searched independently.

### Exclude a Word (Negation with `-`)
```js
db.articles.find({ $text: { $search: "Python -machine" } });
// Returns articles about Python but NOT mentioning "machine"
```

The `-` prefix **excludes** documents that contain that word.

### Search is Case-Insensitive
```js
db.articles.find({ $text: { $search: "java" } });
db.articles.find({ $text: { $search: "Java" } });
db.articles.find({ $text: { $search: "JAVA" } });
// All three return the same results
```

### Search for an Exact Phrase
```js
db.articles.find({ $text: { $search: "\"machine learning\"" } });
// Returns only articles with the exact phrase "machine learning"
```

### Sort by Relevance Score
```js
db.articles.find(
  { $text: { $search: "Java" } },
  { score: { $meta: "textScore" } }
).sort({ score: { $meta: "textScore" } });
// Returns most relevant results first
```

## 11. Key Rules & Limitations

### Index Rules
- By default, MongoDB creates a unique index on `_id` for every collection.
- You can have multiple regular indexes, but only **one text index** per collection.
- Indexes consume disk space and slow down write operations (`insert`, `update`, `delete`) slightly — because the index must be updated too.
- Always create indexes on fields that you **frequently query or filter on**.

### Text Index Rules
- Only **one text index** per collection (can cover multiple fields via compound text index).
- Text search only works with the `$text` operator.
- Text indexes do **not** support regular comparison queries like `{ content: "Java" }`.
- Stop words (common words like "is", "the", "and") are automatically excluded from the index.
- Stemming is applied — "programming" and "program" may both match "program".

### `explain()` Rules
- `queryPlanner` does **not** execute the query (safe for production diagnosis).
- `executionStats` **does** execute the query (use with caution on slow queries).
- If `allPlansExecution` shows no `rejectedPlans`, it usually means only one plan was available (e.g., only one index exists).

## 12. Quick Reference Cheat Sheet

```js
// ── INSERT ──────────────────────────────────────────────
db.col.insertOne({ field: value });
db.col.insertMany([{ ... }, { ... }]);

// ── QUERY ───────────────────────────────────────────────
db.col.find();                              // all documents
db.col.find({ field: value });             // filter
db.col.findOne();                          // first document
db.col.countDocuments();                   // count

// ── INDEXES ─────────────────────────────────────────────
db.col.createIndex({ field: 1 });          // ascending
db.col.createIndex({ field: -1 });         // descending
db.col.createIndex({ field: "text" });     // text index
db.col.getIndexes();                       // view all indexes
db.col.dropIndex("index_name");            // drop index

// ── EXPLAIN ─────────────────────────────────────────────
db.col.find({ field: val }).explain("queryPlanner");
db.col.find({ field: val }).explain("executionStats");
db.col.find({ field: val }).explain("allPlansExecution");

// ── TEXT SEARCH ─────────────────────────────────────────
db.col.find({ $text: { $search: "word" } });          // single word
db.col.find({ $text: { $search: "word1 word2" } });   // OR search
db.col.find({ $text: { $search: "word -exclude" } }); // exclude word
db.col.find({ $text: { $search: "\"exact phrase\"" } }); // exact phrase
```

---

> **Tip:** Always use `explain("executionStats")` when tuning query performance. If you see `COLLSCAN` on a large collection, consider adding an index on the queried field.
